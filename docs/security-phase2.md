# ความปลอดภัยเฟส 2 — คู่มือเจ้าของเว็บ

เฟส 2 ย้ายการตรวจ PIN และการตรวจสิทธิ์ไปไว้ที่ server (Postgres ใน Supabase) หลังเปิดสวิตช์ `enforce`:

- ทุกการบันทึกต้องมี **session token** ที่ server ออกให้ตอนล็อกอิน (อายุ 30 วัน) การปลอม `pp_user_id` ใน DevTools จะเห็นแค่หน้าจอ แต่บันทึกอะไรไม่ได้
- PIN ไม่อยู่ในแถวที่ใครก็อ่านได้อีกแล้ว (เก็บเป็น bcrypt ใน `private.credentials` ซึ่ง API มองไม่เห็น)
- ใส่ PIN ผิด 5 ครั้ง ล็อกบัญชี 15 นาที (ที่ server ลบ localStorage ก็ข้ามไม่ได้) และจำกัด 30 ครั้ง / 10 นาที ต่อ IP
- publishable key ยังอ่านข้อมูลได้เหมือนเดิม แต่ **เขียนตรง ๆ ไม่ได้** ต้องผ่านฟังก์ชัน `pp_save_*` ที่ตรวจสิทธิ์

ไฟล์ SQL: `supabase/migrations/20261019140000_server_auth.sql` (รันซ้ำได้ปลอดภัย)

## ใครแก้อะไรได้ (หลังเปิด enforce)

| ข้อมูล | แอดมิน | เจ้ามือ | ผู้เล่น |
|---|---|---|---|
| ลีก (คะแนน, ซีซั่น, บัญชี, สิทธิ์) | ทุกอย่าง | — | แก้ได้แค่โปรไฟล์ตัวเอง: ชื่อเล่น, คำท้า, รูป, ภาพพื้นหลัง, PromptPay, QR |
| ทายผล | ทุกอย่าง (รวมตั้งเจ้ามือ) | ตลาด, ราคาต่อ, คำนวณผล/ยกเลิก bet | เพิ่ม bet ในชื่อตัวเองเท่านั้น (ตลาดเปิด, ไม่ใช่คู่ตัวเอง, คู่ละครั้ง) |
| ดัมมี่ | ✓ | ✓ | ทุกคนที่ล็อกอิน |
| นับสด (live) | ทุกแมตช์ | — | เฉพาะแมตช์ที่ตัวเองแข่งหรือเป็นคนนับ (ลบรายการที่ค้างเกิน 6 ชม. ได้) |
| คลับ (ท้าดวล, ทัวร์, โหวต, รีแอ็กชัน, เช็กอิน) | ทุกอย่าง | — | สร้างรายการในชื่อตัวเอง, แก้/ลบรายการที่ตัวเองเป็นเจ้าของหรือร่วมเล่น (ผลทัวร์นาเมนต์: ผู้สร้างหรือผู้เข้าแข่งของทัวร์นั้น), รีแอ็กชัน/โหวต/เช็กอิน/คอมเมนต์ของตัวเองเท่านั้น (วันเช็กอินที่เก่ากว่า 29 วันลบทิ้งได้) |

PIN เปลี่ยนได้ทางเดียว: เมนู "เปลี่ยน PIN" (ตรวจ PIN เดิมที่ server) หรือแอดมินกด "รีเซ็ต PIN" (กลับเป็น 1234 และต้องตั้งใหม่ตอนล็อกอิน)

## ขั้นตอน (ทำตามลำดับ)

### 1. รัน SQL (ไม่กระทบเว็บที่ใช้อยู่)

ต้องรัน phase 1 (`20261018130000_harden_shared_state.sql`) และ `20261019120000_club_row.sql` มาก่อนแล้ว

1. Supabase Dashboard → **SQL Editor** สำรองแถวก่อน (ห้ามสร้างตารางสำรองใน `public`):
   ```sql
   create table private.app_state_backup_phase2 as select * from public.app_state;
   ```
2. คัดลอกไฟล์ `supabase/migrations/20261019140000_server_auth.sql` ทั้งไฟล์ วางแล้วกด **Run**
3. ตรวจว่าทุกบัญชีถูกคัดลอก PIN ไปแล้ว (จำนวนต้องเท่ากับจำนวนบัญชี) และสวิตช์ยังปิดอยู่:
   ```sql
   select count(*) from private.credentials;
   select enforce from private.settings;   -- ต้องเป็น false
   ```

ตอนนี้เว็บเก่ายังทำงานเหมือนเดิมทุกอย่าง (PATCH ตรงยังใช้ได้) PIN ที่ใครเปลี่ยนผ่านเว็บเก่าจะถูกคัดลอกเข้า `private.credentials` ให้อัตโนมัติ

### 2. Deploy เว็บใหม่ (มีอยู่แล้วใน PR นี้)

Merge PR → GitHub Pages อัปเดต (อย่าลืม bump `CACHE` ใน `sw.js` ตอน merge) เว็บใหม่ถาม server ว่ามีฟังก์ชันเฟส 2 ไหม (`pp_auth_version`, จำผลไว้ 10 นาที) ถ้ามี จะล็อกอินผ่าน `pp_login` และบันทึกทุกอย่างผ่าน `pp_save_*` ถ้าไม่มี (ยังไม่รัน SQL) จะทำงานแบบเดิมทุกอย่าง

### 3. ให้ทุกคนล็อกอินใหม่หนึ่งครั้ง

- คนที่เปิดเว็บค้างไว้ด้วย session เดิม (ไม่มี token) พอจะบันทึกอะไร เว็บจะขึ้นหน้าต่าง **"ยืนยัน PIN อีกครั้ง"** ใส่ PIN ครั้งเดียวก็ใช้ได้ 30 วัน
- แจ้งในกลุ่ม: "รีเฟรชเว็บ แล้วกดออกจากระบบ/เข้าสู่ระบบใหม่หนึ่งครั้ง" PIN เดิมใช้ได้เหมือนเดิม ไม่ต้องตั้งใหม่
- ทดสอบเอง: แอดมินกรอกคะแนน 1 คู่, ผู้เล่นแก้คำท้าในโปรไฟล์, ทาย 1 ครั้ง, บันทึกดัมมี่ ต้องขึ้น "บันทึกแล้ว" ทุกอย่าง
- ดูว่าใครมี session แล้ว:
  ```sql
  select user_id, max(created_at) from private.sessions where expires_at > now() group by user_id;
  ```

### 4. เปิดสวิตช์

เมื่อทุกคนที่ต้องบันทึกข้อมูล (แอดมิน เจ้ามือ คนนับสด) มี session แล้ว:

```sql
update private.settings set enforce = true;
```

คำสั่งเดียวนี้จะ (1) คัดลอก PIN ที่เปลี่ยนล่าสุดจากแถว (2) **ลบ** `pin`, `pinHash`, `mustChangePin`, `pinChangedAt` ออกจากแถวสาธารณะ (3) ตัดสิทธิ์ UPDATE ตรงของ publishable key (อ่านยังได้) ตรวจผล:

```sql
select count(*) from public.app_state s, jsonb_each(s.league #> '{uidLeague,profiles}') e
where s.id = 'main' and e.value ?| array['pin','pinHash'];       -- ต้องเป็น 0
```

แล้วทดสอบบนเว็บอีกรอบ (กรอกคะแนน / ทาย / แก้โปรไฟล์ / ดัมมี่) เว็บเวอร์ชันเก่าที่ค้างในเครื่องใครจะบันทึกไม่ได้ (ขึ้นออฟไลน์) จนกว่าจะรีเฟรช

## ถอยกลับ (rollback)

```sql
update private.settings set enforce = false;
```

เปิดสิทธิ์ PATCH ตรงกลับมาเหมือน phase 1 ทันที เว็บใหม่ยังใช้ RPC ต่อได้ตามปกติ ข้อควรรู้: PIN ถูกลบออกจากแถวไปแล้ว ดังนั้น **เว็บเวอร์ชันเก่า** จะล็อกอินไม่ได้ (เว็บใหม่ล็อกอินผ่าน server ได้ปกติ) ถ้าต้องถอดเฟส 2 ออกทั้งหมด (ก่อนเปิด enforce เท่านั้น) ดูบล็อก "Full removal" ท้ายไฟล์ SQL — เมื่อไม่มี `pp_auth_version` เว็บใหม่จะกลับไปใช้ PATCH ตรงเองภายใน 10 นาที

## งานประจำ / แก้ปัญหา

- **ลืม PIN:** แอดมินกด "รีเซ็ต PIN" ในหน้าบัญชี → PIN กลับเป็น 1234 และต้องตั้งใหม่ตอนล็อกอิน (session เก่าของคนนั้นถูกตัดทุกเครื่อง) หรือใน SQL Editor:
  ```sql
  select private.reset_credentials('<user id>');
  ```
- **ถูกล็อก 15 นาทีแต่ต้องเข้าเดี๋ยวนี้:**
  ```sql
  update private.credentials set failed_attempts = 0, locked_until = null where user_id = '<user id>';
  ```
- **บังคับทุกคนออกจากระบบ:** `delete from private.sessions;`
- **ข้อความ "ไม่มีสิทธิ์ทำรายการนี้"** = server ปฏิเสธตามกติกาด้านบน (เช่นผู้เล่นพยายามแก้คะแนน) ถ้าเป็นการใช้งานปกติที่ควรทำได้ แจ้งพร้อมข้อความในวงเล็บ แล้วถอยกลับด้วย `enforce = false` ระหว่างแก้
- ห้ามเพิ่ม schema `private` ใน Settings → API → Exposed schemas

## ความเสี่ยงที่ยังเหลือ

- ก่อนเปิด `enforce` ทุกอย่างยังเป็นแบบ phase 1 (ใครมี key ก็แก้แถวได้ รวมถึงเขียน pinHash ใหม่ที่จะถูกคัดลอกเข้า credentials) — ควรเปิดสวิตช์ให้เร็วที่สุดหลังทุกคนล็อกอินใหม่
- แอดมินคือบัญชีที่ทำได้ทุกอย่าง PIN ของแอดมินควรยาว 6 หลักและไม่ซ้ำกับที่อื่น
- คลับ: คีย์ใหม่ที่ฟีเจอร์ในอนาคตเพิ่มเข้ามาใน `club` (นอกจาก matches / challenges / tournaments / social / mvp / checkin) ตรวจแค่ "ล็อกอินแล้ว + ไม่เกิน 1 MB" ต้องเพิ่มกติกาใน `private.club_change_denied` เมื่อเพิ่มฟีเจอร์ ทัวร์นาเมนต์: ผู้เข้าแข่งคนใดก็แก้ bracket ของทัวร์นั้นได้
- ทายผล: server ไม่ตรวจว่าแมตช์มีผลแล้วหรือยังตอนรับ bet (เจ้ามือต้องปิดตลาดเอง เหมือนเดิม) และยอดเงินสูงสุดต่อ bet 1,000,000
- แจ้งเตือน (Web Push) ไม่ได้รับผลจากสวิตช์นี้ แต่ `pp_push_subscribe` เชื่อ user id ที่ส่งมา (ยังไม่ใช้ token) จึงสมัครรับแจ้งเตือนของคนอื่นได้ ควรแก้ในงานถัดไป
- ดัมมี่: ทุกคนที่ล็อกอินแก้ชีตได้ทั้งหมด (เป็นชีตกลางที่ใช้ร่วมกัน) ประวัติยังกู้คืนได้ด้วย `private.restore_app_state`
